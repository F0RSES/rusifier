## 1. Рефакторинг Tf-ремонта

### 1.1 Было и стало

**Было.** `_fallback_tf` выбирал на страницу **один** `Tf` — самый частый среди *заменённых* блоков — и
вставлял его во все `BT` без `Tf`. Если на странице соседствуют разные гарнитуры, непреобразованный
текст получал чужой шрифт.

**Стало.**

| Шаг | Где |
|---|---|
| Снимок `{страница: {block_id: "Tf-оператор"}}` со **всех** блоков **до** первой правки | `DocumentProcessor._run_pdf_engine` |
| Превращение в `{страница: {(y, x): Tf}}` | `DocumentProcessor._tf_maps_by_position` |
| Выбор `Tf` для каждого `BT` без `Tf` по позиции | `pdf_fonts._nearest_tf` |
| Вставка `Tf` + предупреждения о неразрешимых блоках | `pdf_fonts.repair_inherited_font` |
| Запуск ремонта только на страницах с внедрённым CID | `DocumentProcessor._finish_pdf_with_repair` |

Сигнатура ремонта:

```python
repair_inherited_font(
    stream: str,
    fallback_map: Mapping[tuple[float, float], str],  # {(y, x): "/F1 12 Tf"}
    default_tf: str | None = None,
) -> tuple[str, int, list[str]]                          # поток, сколько Tf вставлено, проблемы
```

Ремонт ограничен страницами, где действительно внедрён `/TFCyr0`: текстовое состояние не переносится
между страницами, и лишние вставки `Tf` на остальных страницах только меняли бы байты без пользы.
Пустая карта страницы — не ошибка: `repair_inherited_font` выходит без предупреждений (иначе страница
без извлечённых блоков дала бы по предупреждению на каждый `BT`).

Предупреждения попадают и в лог (`WARNING ремонт Tf: …`), и в `result["warnings"]` — блок без `Tm`
остаётся как есть, но это видно вызывающему коду.

### 1.2 Найденный дефект: направление оказалось важнее расстояния

Первая версия правила ранжировала кандидатов как «сначала блоки выше, потом расстояние»
(`(0 if block_y >= y_pos else 1, |dy|, |dx|)`). На кейсе (d) — Helvetica и Times на одной странице —
это дало:

```
y=694.0 font=TFCyr0  'Обратная связь из встречи была ясной.'
y=674.6 font=F1      'Second helvetica line stays untouched.'
y=494.6 font=F1      'The deadline and roadmap are clear.'      ← Times получил Helvetica
y=474.6 font=F1      'Second times line stays untouched.'       ← Times получил Helvetica
```

Причина: `block.y` из `get_text_layout` — это низ bbox, а `Tm` задаёт **базовую линию**, поэтому
координата блока систематически на ≈0.25 кегля **меньше** `Tm` своей же строки (12 pt → 3 pt).
Собственный блок всегда ранжировался как «ниже» и проигрывал строке на 180 pt выше.

Исправленное правило — близость, направление только как тай-брейк:

```python
rank = (abs(block_y - y_pos), abs(block_x - x_pos), 0 if block_y >= y_pos else 1)
```

После исправления:

```
y=494.6 font=F2      'The deadline and roadmap are clear.'
y=474.6 font=F2      'Second times line stays untouched.'
```

Отдельно проверено, что **прежняя** (до рефакторинга) эвристика ведёт себя так же плохо: при подмене
`_tf_maps_by_position` на «один самый частый `Tf`» Times-строки тоже получают `F1`. То есть кейс (d)
был сломан и раньше — просто не был покрыт тестом.

### 1.3 Что по-прежнему эвристика (честно)

* Совпадение по позиции приблизительное: `(y, x)` — низ bbox, `Tm` — базовая линия. Работает, пока
  межстрочный интервал больше ~0.3 кегля (на практике — всегда).
* Два блока страницы с **одинаковой** `(y, x)` и разными шрифтами неразличимы: побеждает меньший
  `block_id` (детерминированно; задокументировано в docstring `_tf_maps_by_position`).
* `BT` без `Tm` (позиция задаётся только `Td`) — шрифт определить нельзя: блок остаётся как есть и
  попадает в предупреждения. В интеграционном тесте этот путь невоспроизводим: такой блок не
  извлекается движком → замены нет → CID не внедряется → ремонт не запускается. Покрыт unit-тестом
  `test_repair_inherited_font_reports_unknown_position`.

## 2. Harness: 6 кейсов

`tests/test_pdf_realworld.py`, фикстуры генерируются в `tests/fixtures/pdf/` (каталог в `.gitignore`).

| Кейс | Инструмент | replaced | Блоки до→после | Страниц | warnings | Шрифты страницы 1 |
|---|---|---|---|---|---|---|
| (a) `reportlab` | reportlab: `Tf` в отдельном `BT`, текст без `Tf` | 1 | 3 → 4 | 1 | 0 | `F1` Type1, `F2` Type1, `TFCyr0` Type0 |
| (b) `pymupdf` | PyMuPDF: `Tf` в каждом `BT`, текст в hex-`TJ` | 1 | 2 → 3 | 1 | 0 | `helv` Type1, `TFCyr0` Type0 |
| (c) `two_columns` | PyMuPDF, две колонки (x=72 и x=330) | 2 | 6 → 6 | 1 | 0 | `helv` Type1, `TFCyr0` Type0 |
| (d) `mixed_fonts` | reportlab, Helvetica + Times-Roman | 1 | 4 → 5 | 1 | 0 | `F1`, `F2`, `TFCyr0` |
| (e) `existing_type0` | PyMuPDF + TTF → Type0/Identity-H с кириллицей | 1 | 2 → 3 | 1 | 0 | `DejaVuX` Type0 (подмены нет) |
| (f) `five_pages` | PyMuPDF, 5 страниц | 5 | 10 → 10 | 5 | 0 | `helv`, `TFCyr0` |

Общие проверки в параметризованном тесте:

1. `result["success"] is True` и `result["errors"] == []`;
2. `result["replaced_count"]` равен ожидаемому;
3. в извлечённом тексте есть кириллица;
4. каждая нетронутая строка присутствует дословно;
5. **каждый** незамененный блок присутствует целиком (сравнение по нормализованному тексту);
6. текстовых блоков не стало меньше;
7. `pikepdf.open(output)` открывает файл, число страниц совпадает, у каждой страницы есть `/Contents`,
   и файл полностью пересобирается в память (round-trip).

Специфичные проверки:

* (c) обе колонки на местах (`x = 72` / `x = 330`, по 3 строки), порядок строк внутри колонки сохранён;
* (d) незамененные блоки сохранили свои шрифты (`F1` для Helvetica, `F2` для Times) + отдельный
  `test_tf_per_page_map_used_when_mixed_fonts` (разбор content stream через `pikepdf`);
* (e) `/TFCyr0` не появился, набор ресурсов и подтипы не изменились (`/Type0` как и было);
* (f) на каждой из пяти страниц есть «обратная связь».

### 2.1 Наблюдение: длинная замена даёт лишний блок

В кейсах (a), (b), (d), (e) блоков стало на один больше: «обратная связь» длиннее, чем `feedback`, и
движок переносит текст внутри bbox. Это **не потеря** (текст целиком на месте), поэтому критерий в
тесте — «блоков не меньше», а сохранность проверяется по нормализованному тексту всех незамененных
блоков, а не по счётчику. Побочный эффект для читателя: заменённая строка может занять две строки и
сдвинуть контент ниже — штатное поведение `replace_block`.

## 3. Целостность результата

`test_integrity_after_processing` на кейсе (a), замена `The feedback …` → `Обратная связь …`:

| Проверка | Значение |
|---|---|
| `pikepdf.open(output)` | без исключений, страниц 1 |
| `/Resources /Font /TFCyr0` | есть, `/Subtype /Type0`, `/Encoding /Identity-H` |
| `ToUnicode` (bfchar-записей) | 29 |
| Покрытие текста по `ToUnicode` | все символы нового текста присутствуют |
| `/FontFile2` (subset) | 9728 байт, `numGlyphs = 37` |
| CID, реально использованные в content stream | `max = 30 < 37` |

То есть subset непустой, все записанные CID лежат внутри subset, а `ToUnicode` покрывает каждый
символ — текст извлекается читалкой без «кракозябр».

Брались файлы из `/usr/share/doc`; в каждом заменялось первое слово первого блока с латиницей на
«ДАННЫЕ». Критерий — не падение и не порча документа.

|---|---|---|---|

| `shared-mime-info/shared-mime-info-spec.pdf` | 19 | `F55`, `F59`, … (Type1 subset) | `success=False`: `Font cannot encode text and no extensible (Type0/Identity-H) font available in bbox` |

Во всех восьми случаях выходной файл открывается `pikepdf` и PyMuPDF, число страниц совпадает,
исходный текст на месте: **отказ — это явная ошибка в `result["errors"]`, а не испорченный PDF**.

Регрессия на уже согласованном артефакте: `/tmp/report_ru.pdf` (reportlab, 1 страница, 2 блока)
пересобран новым кодом — текст, число страниц и число блоков идентичны.

Наблюдение по LaTeX-документам: это не «баг ремонта», а политика подмены. Подменяем только
base-14-совместимые шрифты (см. `is_base14_font`: семейство матчится по имени, префикс сабсета
`ABCDEF+` отбрасывается). `F55`, `CMR10`, `LiberationSerif` под это правило не попадают, поэтому
кириллицу писать некуда, и движок честно отказывает.

## 5. Готова ли PDF-ветка к продакшену

### 5.1 Что проверено экспериментально

| Утверждение | Как проверено |
|---|---|
| base-14 (и алиасы Arial/TimesNewRoman в т.ч. с префиксом сабсета) → подмена работает | `is_base14_font`: `ArialMT` = `True`, `ABCDEF+Times-Bold` = `True`; кейсы (a), (d), реальные файлы выше |
| Нестандартные семейства → подмены нет | `LiberationSerif` = `False`, `Calibri` = `False`, `Carlito` = `False`, `CMR10` = `False` |
| Type0, в котором **уже есть** кириллица, не подменяется и пишется своим шрифтом | кейс (e): `/DejaVuX` Type0 остался единственным ресурсом, кириллица записана |
| Type0-**сабсет** без кириллицы расширить не удаётся | PyMuPDF + DejaVu, урезанный до `U+0020-007E` → `Font extension failed … missing: ['О','б',…]` |
| Простой TrueType-сабсет расширить не удаётся | reportlab + TTF → `/TrueType`, → `Font cannot encode text and no extensible font available` |

Вывод: «расширение встроенного сабсета» на практике не подтвердилось ни на одном кейсе. Работают
ровно два сценария — подмена base-14 на DejaVu и запись шрифтом, в котором глифы уже есть.

### 5.2 По источникам документов

| Источник | Типичные шрифты | Результат TermRu |
|---|---|---|
| Word → PDF (Arial / Times New Roman) | TrueType/Type0 сабсеты с именами `ArialMT`, `TimesNewRomanPSMT` | **работает**: подмена на DejaVu (шрифт визуально другой, метрики близки) |
| Acrobat Export / Distiller, «печать в PDF» с базовыми шрифтами | Helvetica, Times, Courier | **работает** |
| PDF, где CID-шрифт уже содержит кириллицу | Type0/Identity-H | **работает**, без подмены |
| LibreOffice → PDF (Liberation Serif/Sans) | `ABCDEF+LiberationSerif` | **preflight-отказ** (файл цел, замена не сделана) |
| LaTeX (pdfTeX, dvipdfmx) с CM/LM | Type1/Type0 сабсеты `F1`, `F55`, … | **preflight-отказ** |

### 5.3 Рекомендация

**Для узкого класса — да, для общего случая — пока нет.**

* Можно выпускать как есть, если PDF-ветка заявлена как «base-14 и документы с готовой кириллицей», а
  отказ по прочим шрифтам честно показан пользователем как ошибка блока (сейчас так и есть).
* Нельзя заявлять «PDF любой»: LibreOffice и LaTeX (то есть заметная часть реальных документов)
  получают отказ. Документ при этом не портится, но и замены нет.

Ближайшие шаги, по убыванию эффекта:

1. **Opt-in подмена при невозможности закодировать.** Сейчас гейт — «шрифт base-14». Правильнее —
   «движок не смог закодировать текст» → тогда подставляем DejaVu (флаг
   `--pdf-substitute-fonts=always|base14`, по умолчанию `base14`). Это снимет 4 из 5 отказов на
   реальных PDF из раздела 4 и сделает ветку пригодной для LibreOffice/LaTeX. Цена — текст визуально
   меняет гарнитуру, поэтому только opt-in.
2. **Preflight.** Быстрый проход без записи: «заменяемо N из M блоков, откажут такие-то шрифты» —
   чтобы пользователь не узнавал об отказе после прогона.
3. **Не пытаться расширять сабсеты.** Эксперименты показали, что это тупик; лучше сразу подмена или
   явный отказ.

Отдельно стоит помнить про оформление: подмена всегда меняет гарнитуру блока (DejaVu вместо
Helvetica/Times). Для чтения и поиска это неважно, для точной вёрстки — заметно.

## 6. Как воспроизвести

```bash
cd termru
.venv/bin/python -m pytest -q                      # 131 passed
.venv/bin/python -m pytest tests/test_pdf_realworld.py -v
.venv/bin/python -m src.cli --input report.pdf --output report_ru.pdf --verbose
```

Фикстуры harness создаются в `tests/fixtures/pdf/` при каждом прогоне и в git не попадают.
